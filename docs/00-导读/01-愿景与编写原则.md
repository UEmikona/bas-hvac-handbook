# 愿景与编写原则

## 一、我们想做什么

楼宇自动化（BA）、暖通空调和数据中心基础设施，是一个涉及热力学、流体、自动控制、通信和工程管理的交叉领域。对初学者来说，这个领域有两个常见的困难：

1. **知识零散。** 很多资料只讲某一个设备或某一个模块，学员记住了按钮和步骤，却不知道它们之间的关系。
2. **只知其然，不知其所以然。** 同样是"冷水阀开大，温度降低"，知道原因的人才能在设备异常时判断问题出在哪一环。

本手册希望做到：**每个知识点都回答"是什么"，更要回答"为什么"。** 学习者从原理出发，逐步理解设备、系统和控制逻辑，最后能独立分析问题。

我们也希望这些知识是**公开、可核查、可自由学习的**。任何人都能看到每一条数据的来源，也能提出修改。

## 二、我们坚持的原则

### 1. 实事求是

- **数值必须有来源。** 温度、压力、效率、标准编号等，都要能追溯到标准原文、厂家手册或权威机构资料。
- **不确定的内容要说明。** 如果资料之间有分歧，或者只找到二手来源，就在文中明确标注，不写成确定的结论。
- **常见值与强制值分开写。** 很多数值只是常见设计参考，不同项目可能不同。文中会注明"常见设计值"或"以厂家为准"。
- **错误要公开更正。** 发现错误时，我们以提交记录的形式修正，并保留更正说明。

### 2. 讲清楚原因

每章都包含"为什么这样设计"一节，回答三个问题：

- 这个设备或逻辑为什么存在？
- 如果没有它，会出现什么后果？
- 为什么选择这种方案，而不是其他方案？

### 3. 难点要用通俗的方式解释

对于抽象的概念，我们会使用类比、例子或日常场景帮助理解。类比的作用是帮助入门，不能代替准确的定义。每个难点只用一到两个类比，并且会说明类比在哪里不成立。

### 4. 由浅入深，知识成体系

- 先理论，后设备，再系统，最后调试与运维。
- 每个知识点都标注了前置知识，方便回溯。
- 知识之间的关系通过知识地图展示。

### 5. 不依赖任何机构的专有内容

本手册只使用公开标准、学术资料、厂家公开技术资料和作者自行整理的内容。我们不收录任何培训机构的课件、课程原文、截图或录像，也不复制任何付费课程的结构或表述。

## 三、我们不做什么

- 我们不替代国家标准、设计规范和厂家手册。
- 我们不承诺学完就能独立承担工程项目。实际能力需要现场经验积累。
- 我们不做商业推广，也不推荐特定品牌，除非是为了说明某种技术的公开特点。

## 四、欢迎你参与

知识库的质量取决于读者的反馈。如果你发现错误、表述不清或缺少来源，欢迎提交 Issue 或 Pull Request。详情见 [CONTRIBUTING.md](../../CONTRIBUTING.md)。
