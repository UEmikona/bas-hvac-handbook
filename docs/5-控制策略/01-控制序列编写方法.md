# 控制序列编写方法

> **一句话概括：** 控制序列（Sequence of Operation）用文字描述系统在各种工况下应该怎么动作。它是设计、编程、调试和验收之间的共同依据，写得清楚，系统才能按设计意图运行。

> **篇幅：** 约 1668 字 ｜ **预计阅读：** 约 5 分钟 ｜ **预计学习（含自测）：** 约 50 分钟

## 学习目标

- 说出控制序列的常见组成部分
- 能把一段设备功能描述改写为"条件 → 动作"的结构
- 理解"模式"与"异常工况"在序列中的作用
- 能检查一段控制序列是否存在遗漏或矛盾

## 1. 核心概念

**控制序列：** 按时间、工况或状态，规定设备动作的文字描述或流程说明。

**模式（Mode）：** 系统所处的运行状态，例如停机、预冷、正常运行、夜间待机。不同模式下，控制规则不同。

**设定值（Setpoint）：** 控制的目标值，如送风温度 18 ℃。

**联锁（Interlock）：** 一个设备运行或停止时，另一个设备必须做出的动作。例如风机停止时风阀关闭。

**异常工况（Fault Condition）：** 传感器故障、设备报警、通信中断等非正常状态。序列必须说明如何处理。

## 2. 为什么这样设计

很多楼控项目的问题，不是程序写错，而是**没有人说清楚系统应该怎么做**。设计人员写"AHU 按需运行"，程序员不知道"需要"的标准是什么；运维人员遇到报警，也不知道该保持运行还是立即停机。

控制序列的价值就在于把这些模糊的地方说清楚。**一份好的序列，能让不同的人理解同样的结果。**

💡 **类比：** 控制序列像一份菜谱。"适量盐"这样的描述让厨师无从下手，而"每 500 克肉加 5 克盐"才能让不同的人做出相同的味道。控制序列同样需要把"适量"变成可以验证的数字和条件。

## 3. 系统组成与原理

### 3.1 一份完整序列的常见组成

| 部分 | 应包含的内容 |
| --- | --- |
| 适用范围 | 本序列适用于哪台设备或哪个系统 |
| 输入与输出 | 使用哪些点（传感器、命令、反馈） |
| 运行模式 | 各模式的进入与退出条件 |
| 控制逻辑 | 每个模式下，哪些量被控制，如何控制 |
| 联锁条件 | 设备之间的启停和动作依赖关系 |
| 设定值 | 各设定值的来源、默认值和可调范围 |
| 异常处理 | 传感器故障、设备报警、通信中断时的动作 |
| 报警与记录 | 需要报警的条件，以及需要记录的数据 |

### 3.2 从描述到条件动作

下面是一条不规范的描述：

> "冬季根据情况开启热水阀，保持送风温度合适。"

改写为规范的条件动作形式：

> **条件：** 系统处于冬季模式，且送风温度低于设定值 1 ℃以上。
> **动作：** 以 PID 方式调节热水阀开度，使送风温度趋近设定值。
> **退出：** 送风温度达到设定值，且持续 5 分钟保持稳定。

两者的区别在于：规范的写法给出了**触发条件、执行方式和结束条件**，程序员可以直接对照编写，测试人员也能据此设计测试用例。

> [!NOTE]
> 文中的"1 ℃""5 分钟"只是示例。实际数值应由设计和调试确定，并写入序列中。

## 4. 控制逻辑

编写控制序列的推荐步骤：

1. **列出所有模式：** 停机、启动、正常、待机、故障等。
2. **为每个模式写出进入与退出条件。**
3. **为每个模式写出控制动作，尽量使用可测量的条件。**
4. **列出联锁关系，检查设备之间是否有冲突。**
5. **为每个传感器和设备写出故障处理方式。**
6. **用一个典型工况走一遍，检查是否有遗漏。**

**检查矛盾的常用方法：** 把同一时刻可能同时成立的条件列出来。如果两个条件分别要求阀门开和关，就说明序列存在矛盾，需要明确优先级。

## 5. 常见问题与检查方法

| 常见问题 | 后果 | 检查方法 |
| --- | --- | --- |
| 条件使用"适当""合理"等模糊词 | 程序员和调试人员理解不一致 | 找出所有模糊词，替换为可测量的条件或数值 |
| 只写正常工况，没写故障处理 | 故障时系统行为不可预测 | 为每个传感器和设备单独检查故障路径 |
| 模式之间的切换条件缺失 | 系统可能卡在某个中间状态 | 检查每个模式是否都有明确的进入和退出条件 |
| 两个控制动作互相冲突 | 阀门或风阀来回动作，产生振荡 | 列出同时成立的条件，明确优先级 |
| 设定值来源不明 | 调试时无法确定哪个数值有效 | 为每个设定值注明来源、默认值和可调范围 |

## 6. 小结

- 控制序列是设计、编程、调试和验收的共同依据。
- 好的序列用"条件 → 动作 → 退出"的结构描述系统行为。
- 模糊词是序列的主要风险，应替换为可测量的条件。
- 故障处理与模式切换，和正常控制同样重要，不能省略。
