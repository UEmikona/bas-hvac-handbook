# 排版规范

本规范用于统一全部章节的版式，使读者在不同章节间切换时，结构与阅读节奏保持一致。

---

## 1. 标题层级

| 层级 | 用途 | 示例 |
| --- | --- | --- |
| `#` | 章节标题，每个文件仅一个 | `# 制冷循环基础` |
| `##` | 主要部分 | `## 3. 系统组成与原理` |
| `###` | 子部分 | `### 2.2 为什么要先开水路` |

- 标题使用"编号 + 名称"，编号与名称之间空一格。
- 不跳级使用标题，例如不要直接从 `##` 跳到 `####`。

## 2. 标准章节结构

每章按以下顺序组织，缺省的部分可以删除，但顺序不变：

1. 一句话概括（引用块）
2. 学习目标
3. 核心概念
4. 为什么这样设计
5. 系统组成与原理
6. 控制逻辑
7. 常见故障与排查
8. 小结
9. 知识联动
10. 自测问题
11. 参考资料

### 2.1 知识联动的写法

- 每章列出 3 到 5 个相关章节，格式为"**第 N 章 章名**：为什么相关"。
- 联动说明要写出具体的工程关系（如"阀门特性决定 PID 增益"），不要只写"两者相关"。
- 联动只指向已存在的章节。新增章节时，需要同步更新相关章节的联动列表和[知识网络](知识网络.md)。

## 3. 术语写法

- **首次出现**的专业术语加粗，并在附录术语表中收录。
- 英文缩写首次出现时，写作"中文名（英文全称，缩写）"，例如"楼宇自动化（Building Automation，BA）"。
- 同一概念全文只用一种写法。例如统一使用"冷冻水"，不混用"冷水"。

## 4. 数值与单位

- 数字与单位之间留一个空格，例如 `18 ℃`、`100 kW`、`0–10 V`。
- 百分比使用 `%`，前面留一个空格，例如 `50 %`。
- 数值范围使用 en dash（–），例如 `18–27 ℃`。
- 每个数值都应说明适用条件，例如"常见设计值"或"以厂家为准"。

## 5. 中英文混排

- 中文与英文、数字之间保留一个空格，例如 `BA 系统`、`PID 控制`。
- 中文句末使用中文标点，英文句末使用英文标点。

## 6. 引用与提示框

使用 GitHub 支持的提示语法，统一语义：

| 语法 | 用途 |
| --- | --- |
| `> [!NOTE]` | 补充说明、适用范围 |
| `> [!IMPORTANT]` | 必须注意的原则，如控制方向 |
| `> [!WARNING]` | 可能导致设备损坏或安全风险的操作 |
| `> [!TIP]` 且以"💡 类比："开头 | 用于帮助理解的类比，每个难点最多一个，并须说明类比的局限 |

提示框内容保持简短，一般不超过三行。

## 7. 表格

- 表头使用名词或名词短语，不使用整句。
- 表格列数建议不超过 5 列，超过时拆分为两个表。
- 表格前一行留空，便于阅读器正确渲染。

## 8. 图示

- 简单结构使用纯文本框图（代码块），便于版本管理和无障碍阅读。
- 复杂图示使用 SVG 或 PNG，文件放入 `assets/` 目录，并附文字说明。
- 每张图下方需要一行图注，说明图中的关键信息。

## 9. 代码块

- 代码块必须标注语言，无语言时使用 ` ``` ` 加空白语言标记。
- 点表、控制逻辑等结构化内容，优先使用表格而非代码块。

## 10. 视觉层次的原则

- **一段一个意思**：段落不超过 4–5 行。
- **先结论后细节**：每个小节的第一句话应当给出结论。
- **列表用于并列信息**，**表格用于多维对比**，**编号列表用于有先后顺序的步骤**。
- 避免连续三个以上的加粗或引用块，否则重点会被稀释。
