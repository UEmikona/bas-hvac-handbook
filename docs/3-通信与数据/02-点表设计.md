# 点表设计

> **一句话概括：** 点表（I/O 清单）是楼控系统的"通讯录"，列出每个测量点和控制点的类型、量程、地址与作用。写得清楚，后续的编程、调试和运维都会顺畅；写得含糊，任何环节都会反复返工。

> **篇幅：** 约 1562 字 ｜ **预计阅读：** 约 4 分钟 ｜ **预计学习（含自测）：** 约 40 分钟

## 学习目标

- 说出点表的主要字段，并解释每个字段的作用
- 能区分 AI、AO、DI、DO 四类点，并为每类点选择合适的量程和单位
- 掌握点位命名的基本规则，使名称能直接反映设备和功能
- 能检查一份点表是否存在常见错误

## 1. 核心概念

**点（Point）：** 控制系统中的一个数据或信号，例如一个温度测量值，或一个水泵启停命令。

**点表（Point List）：** 所有点的汇总表，是设计、施工、编程和验收的共同依据。

**I/O 清单：** 与点表含义相近，强调输入与输出的对应关系。

**点位命名：** 为每个点起一个唯一的名字，名字应包含设备、功能和类型。

## 2. 为什么这样设计

点表的价值在于**统一语言**。设计人员、施工人员、程序员和运维人员，都要对着同一张表工作。

如果点表缺少量程、单位或报警限值，程序员就只能猜测，调试时会花大量时间核对。如果命名随意，例如"温度1""温度2"，几个月后就没人能分清它们分别属于哪台设备。

所以点表的目标是：**任何一个看到它的人，都能不问他人就理解每个点的作用。**

## 3. 系统组成与原理

### 3.1 典型的点表字段

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| 点位编号 | 唯一标识 | AHU-01-AI-001 |
| 点位名称 | 中文或英文的功能描述 | 送风温度 |
| 点类型 | AI、AO、DI、DO | AI |
| 信号类型 | 4–20 mA、0–10 V、干接点等 | 4–20 mA |
| 量程 | 测量或输出的范围 | 0–50 ℃ |
| 单位 | 工程单位 | ℃ |
| 控制器地址 | 所在控制器与通道 | DDC-01，通道 5 |
| 报警限值 | 高限、低限 | 高限 30 ℃，低限 5 ℃ |
| 备注 | 特殊说明 | 位于风管中部断面 |

### 3.2 四类点的基本要求

| 类型 | 需要说明的内容 | 注意事项 |
| --- | --- | --- |
| AI（模拟输入） | 量程、单位、信号类型、精度 | 必须说明断线时的处理方式 |
| AO（模拟输出） | 输出范围、单位、执行器类型 | 需说明执行器是比例型还是浮点型 |
| DI（数字输入） | 状态含义（如 1 为运行） | 必须明确"高电平"还是"低电平"代表什么 |
| DO（数字输出） | 命令含义、持续时间或脉冲宽度 | 需说明互锁条件，避免误动作 |

### 3.3 命名规则

一个常用的命名结构是：

```
[系统]-[设备编号]-[类型]-[序号]
```

例如：

- `CHW-01-AI-001`：冷冻水系统 1 号回路的第 1 个模拟输入点
- `AHU-03-DO-002`：3 号空气处理机组的第 2 个数字输出点

> [!IMPORTANT]
> 命名规则应在项目之初就统一，并写入设计说明。中途更改会导致程序、图纸和文档全部要改。

💡 **类比：** 点表像一个大型小区的门牌系统。每户都有唯一的门牌号，门牌号本身就包含了楼栋、单元和层数。好的命名让人一看就知道在哪里，不需要挨家挨户去问。

## 4. 控制逻辑

点表与控制逻辑之间的关系，可以这样理解：

1. 控制逻辑描述"在什么条件下，做什么动作"。
2. 点表规定"条件来自哪个点，动作输出到哪个点"。
3. 程序员按点表连接输入和输出，并按控制逻辑编写判断。

因此，控制逻辑中的每一个条件和动作，都应能在点表中找到对应的点。如果找不到，说明点表缺项或逻辑描述不完整。

## 5. 常见错误与检查方法

| 常见错误 | 后果 | 检查方法 |
| --- | --- | --- |
| 缺少单位或量程 | 程序员猜测，数值换算错误 | 逐行检查，确保每个 AI 和 AO 都有完整的量程和单位 |
| 名称重复或含义不清 | 调试时无法分辨 | 用排序或筛选检查重复名称，确认每个名称能对应到唯一设备 |
| 报警限值与控制设定值冲突 | 控制还没调节到位，就已经报警 | 检查报警限值是否在控制范围之外 |
| DI 的高低电平定义错误 | 设备状态显示相反 | 对照现场接线图，确认每个 DI 的状态定义 |
| 控制器通道分配重复 | 两个点共用一个通道 | 按控制器逐一核对通道号 |

## 6. 小结

- 点表是设计、施工、编程和运维之间的共同依据。
- 四类点（AI、AO、DI、DO）各自需要的信息不同，缺一项就可能导致错误。
- 统一的命名规则，能让系统在多年后仍然清楚易懂。
- 检查点表时，应重点关注量程、单位、状态定义和通道分配。
